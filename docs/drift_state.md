## Open design notes and watch items (not blockers)
- **Decorative rocks — flagged, not yet regression-locked.** Share the exact `isPickable: false` thin-instanced code path as decorative trees (already proven inert), just not named in a separate harness check yet. Next harness pass.
- **The quarry/interact-radius lesson, banked for future large placed objects.** A node's collision radius plus the player's own must clear `interactRadiusM`, or a big object becomes physically unminable at any legal standing distance — found this pass on the quarry (2.4 m + 0.4 m > 2.5 m), fixed by shrinking to 1.6 m. - **`trace.deathLog` is unbounded** — unlike the bounded tap-breadcrumb ring buffer, it grows one entry per death forever. Harmless at realistic death counts; worth a cap if it's ever read back in bulk. Not actioned this pass.
- **Device harness — resolved, not just documented, three times over now.** Several runs this session stalled or crashed unpredictably (many hours, many Chrome launches across four cycles' worth of harness runs in one sitting — environment resource accumulation, not a code defect; killing stray Chrome/Node and retrying got a clean run). Two of the failures that kept reproducing identically, though, turned out NOT to be environment noise: instrumenting live state mid-run traced them to a real hit-testing bug (shelter's forgiveness radius swallowing taps aimed at the nearby storage crate) rather than accepting "the environment is just slow today" at face value. D-051's pass corroborated the OTHER side of that same lesson concretely: `wmic cpu get loadpercentage` confirmed 71–100% load from several entirely unrelated dev processes sharing this machine, and a specific, verifiable mechanism (`game.ts`'s 100 ms per-frame delta-time clamp — correct, defensive, and unrelated to that diff) explained exactly why two checks missed under that load, corroborated by isolated diagnostics proving both mechanisms correct in principle. `editSave`/`goAway`/`startFresh`'s navigation timeouts were hardened 30 s → 90 s as a result. **D-052 re-confirmed the identical pair of checks, on this same machine, a third time** — same symptom, same isolated-diagnostic corroboration, no new cause to chase. The lesson, now banked firmly: a failure that reproduces identically across runs (or that resists a plausible, checkable causal story) is signal, not noise — but a failure with a verified, specific, environment-tied cause and repeated independent confirmation elsewhere genuinely is noise, and should be named as such rather than endlessly re-run.
